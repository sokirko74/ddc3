=head1 DDC *.opt FILE SYNTAX

This manpage describes the syntax of *.opt index
option files ("opt-files") used by the DDC corpus indexing system.

########################################################################
## Description
=pod

=head1 DESCRIPTION

This section contains descriptions of the various options and flags
which may occur in a DDC opt-file, insofar as the author is able
to provide them.  These are for the most part legacy options which
may or may not be fully functional.  I have not tested (most of)
these options for functionality.  The reader is strongly advised
to perform his or her own tests before using any of the options
described below (but particularly the undocumented ones)
in a production environment.

=head2 Sources

DDC opt-files are parsed and processed by the method
CConcIndexator::LoadOptionsFromString()
after intialization of
default option values by the method
CConcIndexator::InitDefaultOptions(),
both of which methods are defined in
F<src/ConcordLib/ConcordOptions.cpp>.
Refer to the source code for further enlightenment.

=cut

##==============================================================
## Option Processor Directives
=pod

=head2 Option Processor Directives

=head3 #comment

Comments are lines starting with a literal hash-mark (C<#>).
Such lines are ignored by the option processor
B<except> for the backwards-compatible L<#include|/include> directive.

=head3 include

 include "OPTFILE"
 #include "OPTFILE"

The C<include> directive inserts the contents of an external opt-file at the
current position.  If OPTFILE is a relative pathname, it is interpreted relative
to the directory containing the top-level .opt file for the current corpus.

Note that for historical reasons, the C preprocessor syntax C<#include "OPTFILE">
is also supported, is B<NOT> a comment, and B<WILL> be evaluated.  This behavior
may change in the future.

=cut

##==============================================================
## Required Declarations
=pod

=head2 Required Declarations

Each DDC option file requires two obligatory declarations L<Lang|/lang> and L<IndexType|/indextype>, which
should occur as the first two options in an opt-file (although they
may be defined by an external file loaded with the L<include|/include> directive).

=head3 IndexType

 IndexType TYPE

Sets the type of the underlying corpus index.
I<TYPE> can be C<DWDS_Index>,  C<MorphXML_Index>, or C<Free_Index>.

Future versions of DDC may support only the C<Free_Index> type.

=head3 LANG

Sets language to use for runtime lexical expansion and possibly index-time analysis.
Known languages are C<German>, C<Russian>, C<English>, and (possibly) C<Generic>.

=cut

##==============================================================
## Boolean Flags and Switches
=pod

=head2 Boolean Flags and Switches

The following options represent boolean flags and switches, which
are set if and only if the corresponding flag appears in the corpus opt-file.
As of ddc v2.0.20, each boolean flag may appear with an optional value argument.
The value arguments C<no>, C<n>, C<false>, C<off>, C<disabled>, and C<0> cause the corresponding
boolean flag to be cleared.  Omitting the value argument or specifying any other value causes
the flag to be set.

Prior to ddc v2.0.20,
there was no way to override a previously set boolean flag:
to disable a boolean option backwards-compatibly, omit it from the opt-file or comment it out.


=head3 Utf8

If specified true, DDC expects all corpus data and external queries to be encoded in UTF-8.
This uses both iconv and C99 locales internally, so you should ensure that your
LC_CTYPE variable has a UTF-8 encoding (e.g. I<export LC_CTYPE="en_US.UTF-8"> in the parent shell.)
if you choose to use this option.

=head3 DisableDefaultQueryLexicalExpansion

If specified and true, DDC will not include the C<infl> term expander to the default expansion
pipeline for the C<Token> index.

Note that a term expansion explicitly defined with an L<Expand|/expand> clause for
the C<Token> index will override the effects of this option.

=head3 CaseInsensitive

If specified and true, DDC will not add the C<case> term expander to the default expansion
pipeline for the C<Token> index.

Note that a term expansion explicitly defined with an L<Expand|/expand> clause for
the C<Token> index will override the effects of this option.

=head3 ShowNumberOfRelevantDocuments

(from DDCReadme):
If set, DDC calculates the number of relevant documents, otherwise the member that holds this number is set to 0.

=head3 QueryOnlyFiles

(from DDCReadme):
If set, DDC doesn’t create a sentence break collection.
Only meaningful for C<DWDS_Index> or C<MorphXML_Index> L<Index Types|/indextype>.

=head3 NoContextOperator

(from DDCReadme):
If set, prohibits context operator (#CNTXT) in the query language.

=head3 AllowUnsafeQueries

If set, any attempt to compile a potentially unsafe query will cause a runtime
exception to be thrown.  Currently, only file-list queries (C<E<lt> FILENAME>)
are considered "unsafe" for such purposes.

=head3 OutputBibliographyOfHits

(from DDCReadme):
If set, then DDC outputs bibliographical information for hits instead of filenames.

=head3 LemmaQueryUsesMorphPattern

If true (default), then DDC will treat C<%LEMMA> queries as C<$Lemma=[LEMMA]>,
i.e. implicitly insert @-delimters around a regex C<LEMMA>.
Otherwise, C<%LEMMA> queries will be treated as C<$Lema=@LEMMA>, i.e. literal matches.
Since ddc v2.0.20.

=head3 IndexChunks

(from DDCReadme):
If set, enables indexing and querying using 'chunks', otherwise chunks are ignored.
Only meaningful for the C<Free_Index> L<Index Type|/indextype>.

NOTE: seems to control implicit creation of a C<Chunk> index.

=head3 IndexMorphPatterns

(from DDCReadme):
If set, DDC creates a C<MorphPattern> index.
Only meaningful for the C<DWDS_Index> L<Index Type|/indextype>.

=head3 IndexPunctuation

(from DDCReadme):
Index punctuation marks only if set.
Only meaningful for the C<DWDS_Index> L<Index Type|/indextype>.

=head3 UseDwdsThesaurus

(from DDCReadme):
Enable creation and use of the C<Thes> thesaurus index if set.
Only meaningful for the C<DWDS_Index> L<Index Type|/indextype>.

=head3 UseParagraphTagToDivide

(from DDCReadme):
If set, the tokenizer seeks C<E<lt>/pE<gt>> in the input 
texts in order to  divide the text into paragraphs.
Only meaningful for the C<DWDS_Index> L<Index Type|/indextype>.

=head3 EmptyLineIsNotSentenceDelim

(from DDCReadme):
If set, an empty line in the input texts is not interpreted as an end of sentence.
Only meaningful for the C<DWDS_Index> L<Index Type|/indextype>.

=head3 DontUseIndention

(from DDCReadme):
If set, DDC  doesn’t use indention (sic; assumedly "indentation" is meant) to find paragraph breaks.
Only meaningful for the C<DWDS_Index> L<Index Type|/indextype>.

=head3 ArchiveIndex

Undocumented

=head3 ResumeOnIndexErrors

Undocumented

=head3 GutenbergInterface

Undocumented

=head3 DwdsCorpusInterface

(from DDCReadme):
If set, enables DWDS-like formatting for output hits.

=cut

##==============================================================
## Single-valued Options
=pod

=head2 Single-valued Options

The following options take a single argument, which may be a list of values.
Each of these options should occur at most once in an opt-file.
Assumedly, in the case of multiple occurrences of the same option, the most recent
declaration "wins".

=head3 Indices

 Indices INDEXLIST

(largely drawn from DDCReadme):
Declares index fields used by the underlying corpus index.
C<INDEXLIST> is a list  of index declarations delimited by semicolons C<;>.
Each index declaration is a string of the form

 [LONGNAME SHORTNAME ARCHIVE STORAGE]

where:

=over 4

=item LONGNAME

is a long name for the index, conventionally in CamelCase;

=item SHORTNAME

is a short name for the index, conventionally in all lower-case and frequently only a single character;

=item ARCHIVE

is one of the strings C<archive> or C<normal>.
If it is C<archive>, the current index is archived, otherwise it is not; and

=item STORAGE

is one of the strings C<storage> or C<storage_omit>.
If it is C<storage>, then the index is supplied with a storage during indexing, otherwise storage is not built.
By default the first index is build with a storage (if it is not manually prohibited), other indices are built without storages.

=back

The L<indices|/indices> option is only supported for the C<Free_Index> L<Index Type|/indextype>.


=head3 IndicesToShow

 IndicesToShow INTLIST

(largely from DDCReadme):
Declares a list of those indices which should be returned in hit responses to user queries.
C<INTLIST> is a space-separated list of integers, where each integer I<i> is the position of some index declaration in the
L<Indices|/indices> declaration, counting from 1;
i.e. for each I<i>, 1 E<lt>= I<i> E<lt>= N_INDICES, where N_INDICES is the number of index declarations by the L<Indices|/indices> option.
For each output word, this list determines the order of the indices whose values are used to represent this word in an output hit.
By default, L<IndicesToShow|/indicestoShow> is C<1>, i.e. words are represented only by the value of the first index
(normally the text of the token itself). If some index is mentioned  inIndicesToShow, then it must have an index storage built during indexing.

Only supported for the C<Free_Index> L<Index Type|/indextype>.


=head3 DefaultBibl

 DefaultBibl NAME

C<NAME> is the name of a fallback bibliographic field to be queried if no literal match is found for a runtime
(user) filter.  C<NAME> must be the name of a bibliographic metadata attribute as defined by the
L<Bibl|/bibl> option.
This option can be used in conjunction with a C<constant> bibliographic metadata attribute
to provide a default value for unknown bibliographic metadata attributes, e.g. to facilitate interoperability
between multiple heterogeneous corpora without the need for re-indexing or explicit definition of
L<Bibl|/bibl> constant fields.
If omitted or set to the empty string (the default), query filters on an undefined bibliographic
attribute will raise a runtime error.

B<CAVEAT>: You should think B<carefully> before using this feature, since it will suppress error and/or warning
messages due to typographical errors for "real" attribute fields.

Since v2.0.27

=head3 HitBorders

 HitBorders BREAKLIST

(largely from DDCReadme):
C<BREAKLIST> is a string of break collection declarations delimited by semicolons C<;>.
Each break collection declaration is a colon-separated string of the form
C<[LONGNAME:SHORTNAME]> or C<[LONGNAME:SHORTNAME:default]>, where

=over 4

=item LONGNAME

is a long name for the break collection, conventionally in CamelCase;

=item SHORTNAME

is a short name for the break collection, conventionally in all lower-case and frequently only a single character; and

=item C<default>

is the literal string C<default>, which if present indicates that the
current break collection is to be used for queries which do not specify any
break collection specification (e.g. using the C<#WITHIN> query operator).

=back

The L<HitBorders|/hitborders> option is only supported for the C<Free_Index> L<Index Type|/indextype>.


=head3 HtmlHighlighting

 HtmlHighlighting TAGS

Set highlighting strings to use for identifying matched tokens in hits returned in HTML format.
C<TAGS> is a string of the form C<L;R;LL;RR>, where
the first matched token I<w> in any hit is marked by C<L>I<w>C<R>,
and subsequent matched tokens in the same hit are marked as C<LL>I<w>C<RR>.
Tag strings support C-style escapes as well as JSON-style unicode (UTF-8) escapes.

Default is:

 HtmlHighlighting <STRONG><FONT COLOR=red>;</FONT></STRONG>;<STRONG><FONT COLOR=red>;</FONT></STRONG>


=head3 TextHighlighting

 TextHighlighting TAGS

Set highlighting strings to use for identifying matched tokens in hits returned in text format.
C<TAGS> is string as described under L<HtmlHighlighting|/htmlhighlighting>.

Default is:

 TextHighlighting &&;&&;_&;&_

=head3 TableHighlighting

 TableHighlighting TAGS

Set highlighting strings to use for identifying matched tokens in hits returned in table format.
C<TAGS> is string as described under L<HtmlHighlighting|/htmlhighlighting>.

Default is:

 TableHighlighting &&;&&;_&;&_

=head3 TokenDelimiter

 TokenDelimiter DELIM

Set delimiter string to be inserted before the data for each token in HTML, Text, and Table output formats.
Prior to DDC release 2.0 (branch 1.80-dx1), this option was not present and token boundaries could not be reliably
determined from the built-in output formats.
The string DELIM may not contain any literal whitespace, but C-style escapes and
JSON-style unicode escapes are supported

For historical reasons, DELIM defaults to an empty string.


=head3 InterpDelimiter

 InterpDelimiter DELIM

Set delimiter string to be inserted between individual index fields for each token in HTML, Text, and Table output formats.
The string DELIM may not contain any literal whitespace, but C-style escapes and
JSON-style unicode escapes are supported
Defaults to C<#>.

For historical reasons, the (misspelled) option C<InterpDelimeter> is an alias for C<InterpDelimiter>.

=head3 LeftKwicContextSize

 LeftKwicContextSize N

(from DDCReadme):
Set the length of the right context to use for each
KWIC line when generating file summaries (snippets).
The default value is 4.

=head3 RightKwicContextSize

 RightKwicContextSize N

(from DDCReadme):
Set the length of the right context to use for each
KWIC line when generating file summaries (snippets).
The default value is 4.

=head3 NumberOfKwicLinesInSnippets

 NumberOfKwicLinesInSnippets N

(from DDCReadme):
Set the number of kwic lines in snippets. The default value is 10.

=head3 MaxRegExpExpansionSize

 MaxRegExpExpansionSize N

(from DDCReadme):
Set the maximum number of indexed items
which can be included in an expansion set of one regular expression.
Default value is 1000000.

=head3 MaxCachedHitsCount

 MaxCachedHitsCount N

Set maximum number of hits to store in a cache entry of an associated CConcHolder (subcorpus server).
Query results with more than C<N> hits will not be cached.
Default=512.

Since v2.0.23 (formerly a global constant = 500).

=head3 MaxQueryCacheSize

 MaxQueryCacheSize N

Set maximum number of queries to be LRU-cached by an associated CConcHolder (subcorpus server).
Default=512.

Since v2.0.23 (formerly a global constant = 500).

=head3 UserMaxTokenCountInOnePeriod

 UserMaxTokenCountInOnePeriod N

(from DDCReadme):
Set the size of internal subcorpora.
The greater the value of this parameter is, the faster
querying procedures work, and the more memory the program needs.

Default if unspecified is hard-coded as 5000000.

=head3 LocalPathPrefix

 LocalPathPrefix STRING

(from DDCReadme):
The common prefix of each corpus filename that should be replaced by
the value of L<InternetPathPrefix|/internetpathprefix> when DDC outputs file names.

=head3 InternetPathPrefix

 InternetPathPrefix STRING

Replaces the value of L<LocalPathPrefix|/localpathprefix> in corpus filenames
if and when they occur in DDC output.

=head3 TfIdfRank

 TfIdfRank FLOAT

(from DDCReadme):
Float parameter (0 E<lt>=FLOAT E<lt> 1) for TFIDF weighting.

=head3 PositionRank

 PositionRank FLOAT

(from DDCReadme):
Float parameter (0 E<lt>=FLOAT E<lt> 1) for position weighting.

=head3 NearRank

 NearRank FLOAT

Float parameter (0 E<lt>=FLOAT E<lt> 1) for NEAR weighting.

=head3 ServerInfo

 ServerInfo KEY VALUE

Sets a constant value to be returned in responses to client 'info' requests
to an associated CDDCLeafServer (see L<ddc_proto>).  KEY is a key string optionally
containing C escapes, and VALUE is a literal JSON value to be returned as the value
of C<user.KEY> in leaf-server 'info' responses.

Since v2.0.34.

=head3 ServerInfoFile

 ServerInfoFile KEY FILENAME

Sets an external filename value to be returned in responses to client 'info' requests
to an associated CDDCLeafServer (see L<ddc_proto>).  KEY is a key string optionally
containing C escapes, and FILENAME is a filename containing literal JSON code to be returned as the value
of C<user.KEY> in leaf-server 'info' responses.  FILENAME is interpreted relative to the directory
containing the project *.con file associated with the leaf server.

Since v2.0.34.

=cut

## Multi-valued Options
=pod

=head2 Multi-valued Options

The following options may occur multiple times in a single opt-file.

=head3 textarea

 textarea NAME XPATH

(from DDCReadme):
Each C<textarea> declaration describes a single text area, where
NAME is name of the text area field, and
XPATH is an X-Path.

=head3 Bibl

 Bibl TYPE VISIBILITY NAME VALUE

(mostly from DDCReadme):
Each C<Bibl> declaration describes a single bibliographical field (such as date of publication, author, and so on).
The bibliographical field can be predefined ("orig", "scan", "date", "page", "pagerank") or free (user-defined).
Predefined bibliographical fields have special processing in DDC, for example, field "scan" is used to build a hit
header. Free bibliographical fields can contain either integer or string data: for both datatypes, one can use
the general filter operator or general order operators (C<#HAS> and C<#LESS_BY> respectively).
The arguments to free C<Bibl> are:

=over 4

=item TYPE

is the type of the bibliographic field; either C<string>, C<integer>, or C<constant>;

=item VISIBILITY

either C<1> or C<0>: if it is "1",  then DDC displays the value of the field for each hit header;

=item NAME

a symbolic name for this bibliographic field (by convention all lower-case); and

=item VALUE

For the C<string> and C<integer> types, C<VALUE> should be an X-Path specification of the location
of the field data in corpus source documents; for
the C<constant> type, it should be a literal string indicating the value to be returned.

=back

Note that additions, deletions, and/or changes to C<constant> bibliographic fields do B<not>
require re-indexing, whereas any changes to non-C<constant> fields B<do>.

Prior to v2.0.30, multiple definitions of a bibliographic field C<NAME> caused a fatal
error when loading a corpus project.  As of v2.0.30, a warning is emitted in these cases,
and the most recent definition is used (later definitions effectively "clobbering" earlier
ones).

Since v1.x; C<constant> fields since v2.0.27, multiple definition since v2.0.30.


=head3 Bigrams

 Bigrams INDEXNAME MAXLEN BREAKNAME

Request construction of an n-gram index at indexing time, suitable for sorting runtime hits
lexicographically by neighbor I<INDEXNAME> using the C<#left> and/or C<#right> query operators.
Up to I<MAXLEN> neighbors are considered for the sort.  Breaks of type I<BREAKNAME> terminate
the sort.
Example usage: C<Bigrams Token 2 s>.

B<OBSOLETE> as of ddc v2.0.19, which supports generic C<#left> and/or C<#right> query operators
on arbitrary token attributes within the current query break collection, provided the indices for 
the attributes in question were built with the L<STORAGE|/STORAGE> option set.

=head3 Expand

 Expand LABEL CLASS PARAM...

Declares a named term expander which can be used to expand index queries
using either the explicit pipeline notation (C<|LABEL|...>), or implicit
expansion heuristics on a per-index basis.  Conceptually,
each expander in a pipeline operates on the set of terms returned by the
previous expander in the pipeline, and the set returned by the final expander
in the pipeline represents that set of index values which qualify as "matches" to the term queried.

I<LABEL> is a label string
used to identify the expander in user-specified pipelines.
If I<LABEL> is also the I<LONGNAME> of an index field declared in L<Indices|/indices>,
then the corresponding expander is used implicitly if no explicit pipeline is
specified or if the default pipeline C<|-> is used.

I<CLASS> is a string representing the expansion function to use, and
I<PARAM...> are additional parameters to the expansion function.
Currently supported expander classes are:

=over 4

=item Id

 Expand LABEL Id
 Expand LABEL Null

Identity expander (no-op).  Parameters: none.

=item Case

  Expand LABEL Case LANG

Letter-case expander (upper- vs. lower-case).
Parameters: C<LANG>, a language string as accepted by the
L<LANG|/lang> declaration.  In particular, the
"language" C<Generic> can be used to specify that
the C99 locale settings should be used to provide
upper/lower-case mappings on wide character strings:
in this case, you must ensure that the I<LC_CTYPE>
enviornment variable for the DDC process is set
appropriately for the corpus and runtime query data.

Note that not all letter-case variants are created
by this expander ("McTaggart problem").

=item ToLower

  Expand LABEL ToLower LANG

Forces all terms to lower-case.
Parameters: C<LANG>, a language string as accepted by the
L<LANG|/lang> declaration, or C<Generic> to use the C99 locale settings.

=item ToUpper

  Expand LABEL ToUpper LANG

Forces all terms to upper-case.
Parameters: C<LANG>, a language string as accepted by the
L<LANG|/lang> declaration, or C<Generic> to use the C99 locale settings.

=item Infl

 Expand LABEL Infl LANG
 Expand LABEL Morph LANG

Inflectional variant expander using built-in morphology
tables.  Parameters: C<LANG>, a language string as
accepted by the L<LANG|/lang> declaration.

=item Cab

 Expand LABEL Cab URL TIMEOUT DEBUG MAPMODE

Orthographic variant expander which queries an external DTA::CAB HTTP server.
Parameters:

=over 4

=item URL

URL of the DTA::CAB HTTP server to be queried with GET request.
The underlying implementation appends a URL-encoded parameter C<qd=DATA>
to this URL before requesting data from the server, where I<DATA> is
a newline-separated list of types to be expanded.
The data format returned by the server is assumed to be a list
of expanded types separated by TABs, newlines, and/or carriage returns.
Empty types in the output are ignored.

=item TIMEOUT

Timeout in seconds for the expansion query.
If the timeout is exceeded, a warning is printed and the
CAB expander behaves like an L<Id|/id> expander, returning
the same set it was passed.

=item DEBUG

Boolean flag for debugging.  If set to a true value, all data
passed to and from the external DTA::CAB server will be echoed
to stderr.  Not for production use.

=item MAPMODE

Boolean flag.  If false or unspecified ("union-mode"), all input terms are
implicitly included to the output set, regardless of whether or not they are
also present in the server's response.  If I<MAPMODE> specified and true, only those
terms explicitly included in the server's response are included in the output set.

=back

=item CabMap

 Expand LABEL CabMap URL TIMEOUT DEBUG MAPMODE

Wrapper for the L<Cab|/cab> class with a default I<MAPMODE>=1.

=item Chain

 Expand LABEL Chain PIPELINE...

Assigns a label to a chain of previously defined expanders.
Takes a C<PIPELINE> of expander labels as its argument:
expander labels in C<PIPELINE> may separated by whitespace
and/or the C<|> symbol (multiple consecutive delimiters are ignored).
Note that an empty expander chain is equivalent to an L<Id|/id> expander.

=back

DDC ensures that the following expander labels are defined,
instantiating them with default parameters only if no other
expander with the same label is explicitly defined in the opt-file:

=over 4

=item id

Defined as C<Expand id Id>

=item null

Defined as C<Expand null Id>

=item case

Defined as C<Expand case LANG> unless the L<Utf8|/utf8> flag was set,
in which case the default I<case> expander is defined as C<Expand case Generic>.

=item infl

Defined as C<Expand infl LANG>.

=item Token

Default expansion chain for the I<Token> index.
Usually defined as C<Expand Token Chain infl case>,
but note that the C<case> component will be omitted from
the default chain unless the legacy L<CaseInsensitive|/caseinsensitive> flag is set,
and the C<infl> component will be omitted if
the legacy L<DisableDefaultQueryLexicalExpansion|/disabledefaultquerylexicalexpansion>
option is set.

=back


=head3 ExpandBibl

 ExpandBibl LABEL TARGET CLASS PARAM...

Declares a named bibliographic expander which can be used in place of a
physically indexed bibliographic fields (as declared with the L<Bibl|/bibl> option)
in #HAS_FIELD queries.

I<LABEL> is a label string
used to identify the expander in user-specified pipelines.
I<TARGET> is the unique I<NAME> associated with a physically indexed bibliographic field used for the underlying query.
If I<LABEL> is also the I<NAME> of a physically indexed bibliographic field declared with L<Bibl|/bibl>,
then the pseudo-field declared with C<ExpandBibl> has precedence when evaluating user queries.

I<CLASS> is a string representing the expansion function to use, and
I<PARAM...> are additional parameters to the expansion function.
Currently (ddc v2.0.5), all I<CLASS>es supported by the L<Expand|/expand> option are also supported
by C<ExpandBibl>, except for the C<Chain|/chain> class.

No bibliographic expanders are defined by default.

=head3 DefaultQueryIndex

 DefaultQueryIndex OPKEY INDEXNAME

Use index C<INDEXNAME> if otherwise unspecified for runtime queries using operator C<OPKEY>.
Known values for C<OPKEY>, the associated query classes, and the associated default values for C<INDEXNAME>
are:


  OPKEY	(INDEXNAME)	CLASS...
 -----------------------------------------------------------------------
   _	(Token)		CQTokInfl
  @_    (Token)		CQTokExact
  %_    (Lemma)		CQTokLemma
  /_/   (Token)		CQTokRegex, CQTokSuffix, CQTokPrefix, CQTokInfix
  [_]   (MorphPattern)	CQTokMorph
 :{_}   (Thes)		CQTokThes
  ^_    (Chunk)		CQTokChunk
  <_    (Token)		CQTokFile
   *    (Token)		none (generic fallback)
   .    n/a		CQTokAnchor

The "." operator key is used by $. queries; its C<INDEXNAME> should resolve to a break name rather than a
token-level index name. Default is whatever break collection was declared as the default.

=cut
