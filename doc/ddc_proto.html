DDC SERVER PROTOCOL

This manual page describes the network protocol used by the DDC (sub)corpus and distributed servers. In the syntax descriptions, the string "\x01" represents a literal ASCII byte with decimal value 1 (the "SOH" [start of heading] character), and " " represents a literal space character (ASCII byte with decimal value 32).

SYNOPSIS

 ##=====================================================================
 ## Message Encoding
 LENGTH DATA
 ##=====================================================================
 ## Distributed Server Messages
 run_query " " CORPUS "\x01" QUERY "\x01" FORMAT "\x01" OFFSET " " LIMIT " " TIMEOUT
 expand_terms "\x01" PIPELINE "\x01" TERMS "\x01" TIMEOUT
 expand_terms "\x01" PIPELINE "\x01" TERMS "\x01" TIMEOUT "\x01" CORPUS
 get_paradigm " " WORD "\x01" ILEMMATIZE " " ILANG
 ddc_close_socket
 ##=====================================================================
 ## Subcorpus Server Messages
 get_first_hits " " QUERY "\x01 " TIMEOUT " " LIMIT
 get_hit_strings " " FORMAT "\x01" OFFSET " " LIMIT
 expand_terms "\x01" PIPELINE "\x01" TERMS "\x01" TIMEOUT
 ddc_close_socket

DESCRIPTION

This section contains descriptions of the various messages which may be sent to a DDC (sub)corpus- or distributed-server and their expected responses.

Message Encoding

 LENGTH DATA

All messages sent to or from a DDC server share a common general format LENGTH DATA, where LENGTH is a 32-bit little-endian unsigned integer, and DATA is the underlying message data, which is exactly LENGTH bytes long.

Distributed Server Messages

run_query

 run_query " " CORPUS "\x01" QUERY "\x01" FORMAT "\x01" OFFSET " " LIMIT " " TIMEOUT

Top-level user query request.

CORPUS

is a vacuous parameter, by convention the string "Distributed" is used.

QUERY

is the user query in DDC syntax (see ddc_query(5) for details).

FORMAT

is a string representing the data format to be returned by DDC. Currently, DDC supports the following formats: "JSON", "TABLE", "TEXT", "HTML", or "DOCIDS".

OFFSET

is the index of the first hit to be retrieved, starting from 0 (zero).

LIMIT

is the maximum number of hits to be retrieved.

TIMEOUT

is the maximum number of seconds

Server response depends on FORMAT. In JSON mode, the response data is a JSON object of the form:

 {
   "istatus_" : 0,              /*-- rsp. istatus_internal status code, 0:success --*/
   "nstatus_" : 0,              /*-- network status code, 0:success --*/
   "error_" : null,             /*-- error string, null:no error --*/
   "nhits_" : 31,               /*-- total number of hits --*/
   "dhits_" : "17+4+10=31",     /*-- distribution of hits over subcorpora --*/
   "ndocs_" : 0,                /*-- (?) number of documents containing hits (?) --*/
   "ddocs_" : "0+0+0=0",        /*-- (?) distribution of hit-documents over subcorpora (?) --*/
   "end_" : 2,                  /*-- index of last returned hit --*/
   "hits_" : [                  /*-- list of hits --*/
     {                                                  /*-- each hit is an object --*/
       "meta_" : {                                      /*-- hit.meta_: bibliographic metadata --*/
            "file_" : "busch_max_1865.xml",             /*-- indexed filename --*/
            "indices_" : ["w","p","l"],                 /*-- indexed token fields for ctx_[1] --*/
            "date_" : "1865",                           /*-- indexed date (decoded) --*/
            "orig_" : "",
            "page_" : null,
            "scan_" : "",
            /*... other indexed metadata fields go here ...*/
       },
       "ctx_": [                                        /*-- hit.ctx_ provides result context --*/
         [ "Ach",",","was","muß","man","oft",... ],    /*-- hit.ctx_[0] is left extra-sentential context (token strings only) --*/
         [                                              /*-- hit.ctx_[1] is the hit sentence itself (structured tokens) --*/
           [ 0, "Wie",      "PWAV",    "wie" ],         /*-- tok[0] is boolean, tok[1] is field meta_.indices_[0], etc --*/
           ...
           [ 1, "Max",      "NE",      "Max" ],         /*-- tok[0] is true iff token matched a term in the user query --*/
           [ 0, "und",      "KON",     "und" ],
           [ 1, "Moritz",   "NE",      "Moritz" ],
           ...
         ],
         [ ...,"heimlich","lustig","machen","." ]       /*-- hit.ctx_[2] is right extra-sentential context (token strings only) --*/
       ],
     },
     /*... other hits go here ...*/
   ]
 }

expand_terms

 expand_terms " \x01" PIPELINE "\x01" TERMS "\x01" TIMEOUT
 expand_terms " \x01" PIPELINE "\x01" TERMS "\x01" TIMEOUT "\x01" CORPUS

Requests online term expansion of the terms TERMS by the expansion pipeline PIPELINE, which must be known to the server (see ddc_opt(5)). TIMEOUT is a request timeout in seconds. If specified, CORPUS is the the name of a subcorpus known to the server which should be queried to perform the expansion. If unspecified, the first registered subcorpus is queried. Response is as for the subcorpus expand_terms command.

get_paradigm

 get_paradigm " " WORD "\x01" ILEMMATIZE " " ILANG

Request morphological analysis of the word WORD using legacy built-in language-specific heuristics. ILEMMATIZE is a boolean integer; if true, only lemmatization is performed. ILANG is an integer indicating the built-in language rule-set to use; it should be a valid MorphLanguageEnum value as defined in ${DDC_SRC}/src/common/utilit.h ; currently recognized values are (0:unknown, 1:Russian, 2:English, 3:German, 4:Generic, 5:URL, 6:Digits).

Response is an HTML fragment.

ddc_close_socket

 ddc_close_socket

Dummy request used internally to avoid annoying complaints unless each subcorpus socket gets exactly 2 messages per user request. DANGEROUS to use on a distributed server, can cause server lockup!

Subcorpus Server Messages

get_first_hits

 get_first_hits " " QUERY "\x01" TIMEOUT " " LIMIT

Requests subcorpus-local evaluation of the user query QUERY. TIMEOUT is an operation timeout in seconds, and LIMIT is the maximum number of hits to evaluate.

If an error occurs, the response is of the form:

 STATUS 0 0 0 0 "\n" ERROR

where STATUS is a non-zero decimal integer error code, and ERROR is a text string describing the error.

On success, responses have the form:

 STATUS MAXHIT NHITS NDOCS SORTED HITIDS

where STATUS is a decimal integer status, 0 (zero) for success, MAXHIT is the index of the last hit computed (?? see CConcHolder::GetHits(q, __EndHitNo__)), NHITS is the number of hits found (?? see CConcHolder::m_AllHitsCount), NDOCS is the number of relevant documents found (?? see CConcHolder::m_RelevantDocumentCount), SORTED is a Boolean integer indicating whether or not the hits should be sorted, and HITIDS is a TAB-separated list of NHITS hit-identification triples (see CConcHolder::GetHitIds())., each element being of the form:

 INDEX " " ORDERID " " ORDER_STRING

where INDEX is the query-dependent hit index, ORDERID is a global sort key for the hit, and ORDER_STRING is either "<empty>" or a string sort-key for the hit (the latter just in case the query contained a context-dependend sort operation such as #left or #right).

get_hit_strings

 get_hit_strings " " FORMAT "\x01" OFFSET " " LIMIT

Requests verbose hit strings for the current query (assumedly the query itself was specified in the previous get_first_hits request). Hits are to be formatted in FORMAT, which should be a format known to DDC. OFFSET is th offset of the first hit to return, starting from zero, and LIMIT is the maximum number of formatted hits to return.

If an error occurred, the response will be of the form:

 STATUS "\x01" "\n" ERROR

where STATUS is a non-zero decimal integer error code (DDCErrorEnum InternalError), and ERROR is a text string describing the error.

On success, the response is of the form:

 C<STATUS> "\x01" HIT_STRINGS "\x01"

where STATUS is a decimal integer zero ("0") and HIT_STRINGS are the formatted hit strings, separated by "\x01". By convention, each hit is terminated by "\n" and preceded by "\x01". For "JSON" format hit strings, the first character of the first hit is a "[" character, the final character of all non-final hits is a "," character, and the final character of the final hit is a "]" character, so hits can be parsed as raw JSON data by removing the initial STATUS code and all "\x01" characters from HIT_STRINGS before parsing.

An example response in JSON format is:

 0\x01[{"meta_":{"file_":"dannhauer_catechismus05_1654.xml",...},"ctx_":[[],[...],[]]},
 \x01{"meta_":{"file_":"frentzel_schauplatz_1744.xml",...},"ctx_":[[],[...],[]]},
 ...
 \x01{"meta_":{"file_":"busch_max_1865.xml",...},"ctx_":[[],[...],[]]},
 \x01{"meta_":{"file_":"frege_sinn_1892.xml",...},"ctx_":[[],[...],[]]}]
 \x01

expand_terms

 expand_terms "\x01" PIPELINE "\x01" TERMS "\x01" TIMEOUT
 expand_terms " \x01" PIPELINE "\x01" TERMS "\x01" TIMEOUT "\x01" ...

Requests online term expansion of the terms TERMS by the expansion pipeline PIPELINE, which must be known to the subcorpus server (see ddc_opt(5)). TIMEOUT is a request timeout in seconds.

Response data is of the form

 STATUS NTERMS "\n" DATA

where STATUS is a decimal integer indicating the operation status (0 indicates success). NTERMS is the number of expanded terms being returned in the DATA portion, and DATA is either an error message (just in case STATUS is non-zero) or a list of expanded terms separated by TABs, newlines, and/or carriage returns (ASCII 0x09, 0x0a, and 0x0d).

ddc_close_socket

 ddc_close_socket

Dummy request used internally to avoid annoying complaints unless each subcorpus socket gets exactly 2 messages per user request. Should always return the response "ok". Causes the server to terminate the client connection.
