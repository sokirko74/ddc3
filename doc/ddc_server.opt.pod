=head1 ddc_server.opt FILE SYNTAX

This manpage describes the syntax of F<ddc_server.opt>
server option files ("server-opt files") used by the DDC corpus indexing system.

=cut

########################################################################
## Synopsis
=pod

=head1 SYNOPSIS

 ##-------------------------------------------------------------
 ## Option Processor Directives

 //comment
 include "OPTFILE"

 ##-------------------------------------------------------------

 ##-------------------------------------------------------------

########################################################################
## Description
=pod

=head1 DESCRIPTION

This section contains descriptions of the various options and flags
which may occur in a DDC server opt-file as read by the
C<ddc_daemon> program versions v2.1.0 and later.
Except where otherwise noted, options are supported by DDC versions v2.1.0 and later.

Note that corpus option-files (F<CORPUS.opt>) are documented independently;
see L<ddc_opt(5)|ddc_opt> for details.

=cut

##==============================================================
## Option Processor Directives
=pod

=head2 Option Processor Directives

=head3 #comment

=head3 //comment

Comments are lines starting with a literal hash-mark (C<#>) or two adjacent slashes (C<//>).
Such lines are ignored by the option processor.

=head3 include

 include "OPTFILE"

The C<include> directive reads in the contents of an external server-opt file at the
current position.  If OPTFILE is a relative pathname, it is interpreted relative
to the directory containing the file currently being parsed.

=cut

##==============================================================
## Logging Options
=pod

=head2 Logging Options

The following options control the verbosity of server log messages.

=head3 LogLevel

 LogLevel LEVEL

Aliases: LogLevel, Log, Verbose

Set the default maximum log-level for server messages to I<LEVEL>,
which should be one of the following:

=over 4

=item silent

Suppress (almost) all log messages.
Aliaes: silent, none, no, off.

=item error

Log only error messages.
Aliases: error, errors.

=item warning

Log error and warning messages.
Aliases: warn, warning, warnings.

=item info

Log errors, warnings, and basic info messages.
Aliases: info, default, weak, light.

=item debug

Log errors, warning, info, and debugging messages.
Aliases: debug, medium.

=item trace

Log everything we can.
Aliases: trace, heavy.

=back



=head3 SlowQueryTimeout

 SlowQueryTimeout SECONDS

Aliases: SlowQueryTime

Default: 10

Log any requests whose processing requires at least I<SECONDS> second(s) as "slow queries".
I<SECONDS> is parsed as a double-precision float, so non-integral numbers can be specified,
but will only be meaningful if DDC was compiled with high-resolution clock support -- in
this case, your DDC logs should show nanosecond resolution.


=head3 StatsWindow

 StatsWindow SECONDS

Aliases: StatWindow, MovingAverageWindow

Default: 600

Size of the time window for tracking moving average statistics, in seconds.
Currently affects only the C<qtavg> status property (average query time).

Since v2.1.1.

=cut


##==============================================================
## Client-Thread and Parallelization Options
=pod

=head2 Client-Thread and Parallelization Options

The following options control the behavior of per-client "worker" threads.

=head3 NumThreads

 NumThreads NTHREADS

Aliases: NumThreads, NThreads, Threads, NumWorkers, NWorkers, Workers

Default: 0

Specifies the number of client worker threads to be used.
If I<NTHREADS> is zero (the default), no client
worker-threads are created and C<ddc_daemon> runs in pure serial mode,
as for DDC E<lt> v2.1.0.
Otherwise,
I<NTHREADS> worker threads will be initialized on server startup for
each server node (branch- or leaf-server), in addition to the
"main" server threads themselves (which are always allocated),
and C<ddc_daemon> will be started in "client-thread" mode.
In this mode, the "main" server threads are only responsible
for accepting incoming client connections and enqueueing them
for later processing by a worker thread, so that up to
I<NTHREADS> simultaneous client connections can be handled
in parallel.

=head3 ThreadQueueSize

 ThreadQueueSize QSIZE

Aliases: ThreadQueueSize, QueueSize, QSize

Default: 256

Specifies the maximum number of pending client connections in the
work queue in client-thread mode (see L</NumThreads>).
If all worker threads are occupied
and I<QSIZE> additional client connections have been accepted and
enqueued for processing, then the main accepting server thread will block
until the queue shrinks below I<QSIZE> before enqueueing any new client
connection -- this basically just pushes the burden of client-queueing
beyond I<QSIZE> to the TCP stack.

=head3 HitStringsParallel

 HitStringsParallel BOOL

Aliases: HitStringsParallel ParallelHitStrings

Default: false

If specified and true, branch servers created by this process will send
L<C<get_hit_strings>|ddc_proto/get_hit_stings> requests to their immediate
daughters in parallel.  If the daughters need to fetch hit data from secondary
storage (i.e. if you don't have excessive amounts RAM), enabling this option
is likely to actually slow things down unless your secondary storage device
supports ultra-low-latency random access reads, in which case it might help.
The parameter C<BOOL> is any string recoginized as a Boolean value;
see L<ddc_opt/"Boolean Flags and Switches"> for details.

Since v2.1.12.

=cut

##==============================================================
## Navigation Cache Options
=pod

=head2 Navigation Cache Options

The following options control the behavior of the branch server navigation hint cache.
Introduced in ddc v2.1.9, the navigation hint cache is an LRU cache used
by C<CDDCBranchServer> nodes to minimize bandwidth requirements and
memory consumption for sequential requests through all hits for a single
query string, typically with monotonically increasing offsets and
result-sets of constant size.

=head3 NavCacheSize

 NavCacheSize SIZE

Aliases: NavCacheSize, NavCacheCapacity

Set the default branch-server navigation hint cache capacity to C<SIZE>
(default=1024).

Since v2.1.9.

=head3 NavCacheStep

 NavCacheStep STEP

Aliases: NavCacheStep, NavCacheStepSize

Set the minimum offset increment for branch server navigation cache updates to C<STEP>
(default=1000).
If C<STEP> is zero, a branch server's navigation hint cache will be updated for each page of hits retrieved.
Otherwise, the cache will only be updated with a new entry if the
difference between the candidate entry's offset and the maximum offset already
cached for the associated query is greater than or equal to C<STEP>.
Setting C<STEP> to a value greater than the default initial page size (usually 10)
should serve to minimize cache turnover and increase the life expectancy of "real"
hit-paging operations without the heavy performance penalties of ddc E<lt>= v2.1.8.

Since v2.1.11.

=cut

##==============================================================
## Compatibility Options
=pod

=head2 Compatibility Options

The following compatibility options are supported:

=head3 VersionCompat

 VersionCompat VERSION

Aliases: VersionCompat, CompatVersion, Compatibility, Compat

Simulate the behavior of a server running DDC version C<VERSION>.
In particular, a branch server with running in version C<VERSION>
compatibility mode should B<NOT> send any requests to its immediate
daughter corpora which cannot be handled by DDC version C<VERSION>.
By default, C<VERSION> is the version of DDC used by the running
server process.

Useful values:

=over 4

=item C<VERSION> E<lt>= 2.1.8

Prevents server from sending navigation hints
in generated C<get_first_hits> requests, or returning
them in C<get_hit_strings> responses.
See L<ddc_proto(5)|ddc_proto> for details.

=back


Since v2.1.9.

=cut
